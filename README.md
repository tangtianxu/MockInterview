# 模拟面试练习 · MockInterview

当前版本：1.0.16。

[下载 Windows 64 位安装包](https://github.com/tangtianxu/MockInterview/releases/download/v1.0.16/MockInterview_1.0.16_x64-setup.exe) · [查看 1.0.16 发布说明](https://github.com/tangtianxu/MockInterview/releases/tag/v1.0.16)

面向 Windows 10 / 11 的中文技术面试练习桌面应用。用户设置目标岗位、关注主题、练习范围、难度和时长后，模型逐题扮演面试官；用户可以输入回答，也可以用麦克风转写回答。每题提交后，应用显示参考评分、回答中的实际片段，以及值得进一步说明的方面。

这个工具用于练习表达和检查知识盲区。模型评分可能不准确。涉及项目经历时，反馈只指出回答思路和可补充的方面。

## 开始前准备

| 项目 | 要求或用途 |
| --- | --- |
| 系统 | Windows 10 / 11，64 位，处理器支持 AVX2。当前发布在 Windows 11 实机验证；Windows 10 的录屏保护需要区分系统版本，见下文。 |
| 出题与评价模型 | 选择本地 Ollama 模型，或配置支持的云端 API。至少需要一个可用的回答生成模型。 |
| 网络 | 首次下载本地模型和使用云端 API 时需要联网；已经安装的本地模型可在本机运行。 |
| 麦克风 | 只有选择语音作答时才需要。也可以全程在输入框中手动填写回答。 |
| 简历 | 技术基础练习不需要简历；项目、技术＋项目、综合练习需要先导入并分析简历。 |

安装 Windows 安装包后，打开桌面上的“模拟面试练习”。升级时使用同一安装包覆盖原安装位置。应用设置和简历文件存放在安装目录之外；正常覆盖安装不要求重新填写模型地址和岗位资料。每次启动默认进入模拟面试练习，并开启窗口录屏排除与隐藏任务栏（包括 Alt+Tab）。在“设置 → 界面与隐私”中可随时恢复普通模式；本次关闭后，下次启动会重新开启。默认恢复快捷键为 Ctrl+Shift+`，冲突时尝试 Ctrl+Alt+Shift+F12；两者均无法注册时保留任务栏入口并显示错误。录屏排除仅对遵循 Windows 捕获排除机制的采集方式有效。Windows 10 2004（build 19041）及以后支持窗口排除；更早的 Windows 10 使用兼容遮挡，录屏中可能出现黑块，无法保证显示窗口背后的画面。设置页会读取实际系统版本并显示当前机制，其他捕获方式仍需实际验证。[微软机制说明](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setwindowdisplayaffinity)

首次打开练习页会展示使用指南，先准备四项：连接生成模型、下载语音模型、检查音频设备、填写个性化资料。生成模型完成状态来自实际聊天检测，语音模型来自完整文件检测，音频设备自动检查所选输入与输出的可用格式；它们不能通过点击“已完成”手动标记。个性化资料可填写或点击“先跳过个性化资料”。下载显示进度、校验、解压与失败原因。点击“已了解，收起指南”后不再自动展开；需要回看时，点击练习页左侧的“使用指南”。下载由你点击后开始，指南不替你注册、充值或未经确认发送简历。

身份背景、目标岗位、关注主题、自我介绍稿和回答要求统一位于“设置 → 个人资料”。模型服务、接口、密钥与本地模型路径位于“设置 → 模型与服务”。两个设置页分别管理个人资料与连接配置；已有填写项会继续保留。

如果只想先看完整流程，可以选择“技术基础”、键盘输入回答，并使用已配置的本地或 API 回答模型；此流程不需要导入简历，也不需要配置语音识别。

## 新手推荐配置与安装顺序

建议先用“本地流式识别＋DeepSeek Flash API”跑通一轮技术基础练习。语音识别模型把声音转成文字；出题与评价模型负责理解文字、提问、复盘和生成参考答案。DeepSeek Flash 是后者，不能代替语音模型。

| 环节 | 推荐选择 | 选择理由与限制 |
| --- | --- | --- |
| 本地流式语音识别 | Sherpa-ONNX Paraformer 中英双语流式，约 226 MB | 先尝试这款，下载包较小，支持持续输出增量文字；下载与识别均不需要 Ollama。 |
| 本地流式语音识别备选 | Sherpa-ONNX Zipformer 中英双语流式，约 511 MB | 同样推荐；用相同语音与 Paraformer 比较术语准确率和响应速度，保留更适合自己声音的一款即可。 |
| 出题、评价、参考生成 | DeepSeek 官方 API，模型 ID `deepseek-flash` | 推荐新手先使用，省去本地生成模型的硬件与部署选择。按调用量计费，需要网络；响应速度也受服务和网络影响。 |
| 免费本地生成备选 | Ollama＋`qwen3:4b-instruct` | 无 API 调用费，但需要下载权重并使用本机内存、算力。小模型可能遗漏机制、误解术语或给出不合理评分，不作为新手首选；适合本地处理与离线练习。 |

这里推荐两款流式语音模型不表示其中一款已经在所有口音、设备或领域上更准确。它们来自软件已适配的列表，运行库随安装包提供，不需要另装 Python 或 Sherpa 开发环境。两款都下载也可以，但每次只使用当前选中的一款。

DeepSeek Flash API 的预算参考：一场面试约 1 元 token 费用。这不是固定套餐或费用上限，实际费用随时长、请求频率、缓存命中与平台价格变化，以平台账单为准；可在历史会话中查看各阶段返回的用量。[官方计费说明](https://api-docs.deepseek.com/zh-cn/quick_start/pricing/)

### 第一步：选择 API 或本地生成方案

推荐选择 API：若选择使用 API，则无需安装、连接或启动 Ollama，简历分析也可直接使用所选 API，每次发送简历文字前明确确认。在第一步获取并填写密钥，检测聊天连接。本地流式语音识别使用独立模型，与生成模型方案无关。

#### API 分支：获取密钥与填写密钥

1. 打开 [DeepSeek 官方 API 平台](https://platform.deepseek.com/)，注册或登录。网页版聊天服务与 API 是两种使用入口；可以聊天不表示已准备好 API 密钥和可用余额。
2. 在平台按需充值或确认可用额度，进入 [API 密钥页面](https://platform.deepseek.com/api_keys)，创建并复制密钥。不要把密钥发给其他人或贴进简历。
3. 在软件“设置 → 模型与服务”的模型服务中选择“DeepSeek 官方”。
4. 粘贴密钥，点击“检测并连接”。预设自动填入 `https://api.deepseek.com` 和 `deepseek-flash`；通常无需手动填写高级设置。
5. 等待实际聊天检测通过。余额不足、密钥无效或网络错误时，先按显示原因解决，再开始练习。
6. 如保留独立模型连接，确认“回答生成”使用这条 DeepSeek 连接。出题、评价和参考生成使用当前回答模型；语音识别继续使用第二步的本地模型。

截至 2026-10-10，官方文档使用的 Flash 模型 ID 为 `deepseek-flash`。具体版本和费用以 [DeepSeek 官方模型与价格页](https://api-docs.deepseek.com/zh-cn/quick_start/pricing/)为准。本应用的 DeepSeek 预设使用非思考模式以减少等待；这不保证每次响应都快，也不保证答案与评分完全正确。

不想使用 API 时，在模型连接中选“本地 Ollama”并检测已下载模型即可。建议先用技术基础题检查术语理解、机制说明和评分，再决定本机模型是否满足要求。简历分析、出题和评价都可沿用当前生成模型；项目相关 API 请求发送简历内容前会逐次征求同意。

只有选择免费本地生成方案时才需要 Ollama，操作如下：

1. 打开 [Ollama 官方 Windows 下载页](https://ollama.com/download/windows)，下载并安装。
2. 返回软件“设置 → 模型与服务 → 本地 Ollama”，点击“重新检测”。没有找到时点击“选择文件”，选择安装位置中的 `ollama.exe`，不要选择安装包或其他程序。
3. 在“下载本地模型”中填写 `qwen3:4b-instruct`，点击“下载模型”，等待完成。这是本地生成模型，与下一步的语音模型分别下载。
4. 若提示服务未启动，点击“启动 Ollama”。本机默认地址为 `http://127.0.0.1:11434`。
5. 在模型连接中选择“本地 Ollama”，选中刚下载的模型，点击“检测并连接”。仅找到程序不代表模型已经下载或服务可以生成回答。

也可以在 PowerShell 执行 `ollama pull qwen3:4b-instruct` 下载，再回软件检测。[Ollama 模型页](https://ollama.com/library/qwen3:4b-instruct)提供对应模型说明。首次下载需要联网；本地方案的“免费”指没有 API 调用费，不代表不占用硬件资源。

### 第二步：下载本地流式语音模型

1. 打开“设置 → 模型与服务 → 语音识别”。
2. “运行方式”选“本地模型”；“识别引擎”选“Sherpa-ONNX · 中英双语流式”。
3. “识别模型”先选“Paraformer 中英双语 · 流式”，点击“下载所选模型”。也可改选 Zipformer 作为备选。
4. 等待下载、SHA-256 校验和解压全部结束，确认状态已下载。预留比下载包更大的磁盘空间；不要在解压未完成时开始语音作答。
5. 在“设置 → 音频设备”选择实际使用的麦克风。接耳机后也要确认选中的是耳机麦克风或你准备使用的独立麦克风。

只用键盘作答可以直接开始练习；指南的语音准备项仍以完整模型检测为准，不提供手动完成按钮。下载 Whisper 并不等于下载了这两款流式模型；本指南优先采用流式识别方案。

### 下载来源与网络要求

“需要 VPN”不能对所有网络一概而论。下面注明应用当前实际使用的来源：国内站点通常可直连，境外站点在部分校园、公司或家庭网络下可能需要可用的 VPN/代理。只有本地生成模型的下载与运行依赖 Ollama，推荐语音模型下载不依赖它。

| 内容 | 当前来源 / 路线 | 国内网络与 VPN/代理 |
| --- | --- | --- |
| 推荐 Paraformer、Zipformer 双语语音模型 | ModelScope 国内镜像，文件重定向至 ModelScope 国内 CDN | 通常无需 VPN；应用优先直连，连接失败后尝试系统/环境代理。国内镜像也可能故障或被所在网络限制。 |
| Whisper 模型 | Hugging Face 境外源 | 未配置国内镜像，部分网络需要 VPN/代理。新用户优先使用上面的双语流式模型。 |
| Ollama 安装程序 | Ollama 境外官方站点 | 本应用未提供国内镜像，访问慢或失败时可能需要 VPN/代理。选择 API 分支无需下载。 |
| Ollama 本地生成模型 | 由 Ollama 从其官方模型仓库下载 | 境外下载链路，部分网络需代理；与语音模型的国内镜像无关。代理设置由 Ollama 管理，参见 [官方代理说明](https://docs.ollama.com/faq#how-do-i-use-ollama-behind-a-proxy)。 |
| DeepSeek 官方 API 平台与 API | DeepSeek 官方服务，非镜像 | 通常可国内直连，无需 VPN。仍需有效密钥、额度和可访问网络。 |
| 软件安装包与自动更新 | GitHub Releases 境外源 | 暂无国内镜像，部分网络需要 VPN/代理，速度取决于实际访问情况。 |
| B 站测试素材 | Bilibili | 通常国内直连；素材可用性由网站决定。 |

### 语音模型下载失败与手动准备

下载按钮会保留“连接中、下载中、校验中、解压中”的状态，失败时显示具体原因。成功只在文件校验、解压和检测通过后打勾。失败后可直接点击重试；当前重新下载完整文件，暂不支持断点续传。

1.0.15 修复了旧下载器缺少应用请求标识（User-Agent）导致 ModelScope 返回 HTTP 403 的问题，也修复了失败原因被隐藏、残留文件阻止重试的问题。旧版遇到“点下载后又回到下载按钮”时，请先更新；并非都由 VPN 或 Ollama 引起。其他网络、目录和磁盘问题仍需按实际错误处理。

- **超时、连接或代理错误**：检查网络和代理是否运行，必要时换一个网络重试。推荐语音模型走国内镜像，不需要为了它先启动 Ollama。浏览器能访问网站不代表应用使用的代理或证书配置一定相同。
- **HTTP 错误、返回网页或 SHA-256 校验失败**：可能是下载源故障、代理拦截、损坏文件或源文件更新。请重试或用“浏览器下载所选模型”，不要关闭证书检查或跳过应用校验。
- **目录无法写入、写入或解压失败**：选择当前用户可写的模型总目录，检查磁盘空间；两款推荐模型可预留至少 2 GB，用于压缩包、解压和替换临时文件。
- **手动下载后仍未检测到**：不要仅把压缩包放入目录。先解压 `.tar.bz2`，把完整模型文件夹放在下述位置，然后选择其上层“模型总目录”并点“重新检测”。不要改模型文件夹名称，也不要额外嵌套一层。手动文件请只使用软件按钮提供的对应来源；手动检测文件布局不等于重新执行下载包的 SHA-256 校验。

```text
你选择的模型总目录/
└─ sherpa_bilingual/
   ├─ sherpa-onnx-streaming-paraformer-bilingual-zh-en/
   │  ├─ encoder.int8.onnx
   │  ├─ decoder.int8.onnx
   │  └─ tokens.txt
   └─ sherpa-onnx-streaming-zipformer-bilingual-zh-en-2023-02-20/
      └─ 原模型包中的 encoder、decoder、joiner 和 tokens 文件
```

下载一款即可，不必同时建立两款目录。Whisper 的 `.bin` 文件则放在模型总目录的 `whisper_cpp` 子文件夹。已有模型目录中的文件不会因切换到 API 方案而删除。

### 第三步：检查音频设备

指南会自动检查所选麦克风和输出设备是否存在、是否提供可用的音频格式。点击“选择音频设备”修改，再点击“重新检测音频设备”重试；不是自行勾选完成。耳机、USB 声卡或蓝牙设备切换后，请重新确认选择。

这一步不录音、不发送音频，也不能代替实际转写测试。模拟练习中点击“麦克风作答”后，检查实际声音是否能被转写；打不开设备、没有权限、识别模型不完整等问题会显示错误。全程键盘作答仍可以直接进行技术基础练习，指南的设备状态不会因此被假定为已完成。

### 第四步：填写个性化资料

在“设置 → 个人资料”按需填写岗位与关注主题、领域背景、自我介绍和回答要求。个人简历可在指南或练习设置中上传并分析。资料是可选项；项目练习需要先完成简历分析，技术基础练习可以跳过简历。填写任一资料后，指南自动识别完成；也可点击“先跳过个性化资料”，以后再补充。

## 五分钟完成第一次练习

1. 打开“设置 → 模型与服务”，选择模型服务。使用预设 API 服务时粘贴密钥，点击“检测并连接”；地址和推荐模型会自动填好。使用本地 Ollama 时先安装程序并下载模型，再检测连接。练习中的出题和评价都使用当前选定的模型连接。已有的独立模型配置会保留。
2. 返回练习页，在“练习设置”中选“技术基础”、难度“中等”、时长“10 分钟”。“目标岗位”和“关注主题”可以留空。
3. 点击“开始练习”。模型会给出一道中文面试题，页面开始倒计时。
4. 像真实面试一样口头回答。把刚才实际说出的内容写进输入框，或者点击“麦克风作答”进行转写。转写文字可以再检查和修改。
5. 点击“提交回答”。页面显示本题参考评分和复盘；确认后点击“下一题”。
6. 到时会结束当前练习；也可以随时点击“结束练习”。重新开始会开启一轮新的题目与计时。

例如，把关注主题填为“Redis 缓存”，模型可能询问缓存穿透的原因与处理方式。回答后请检查复盘指出的是定义、机制、取舍还是边界，再用自己的知识和真实经历补充。

## 用 B 站视频测试练习效果

建议从短片段开始，先测试连接与转写，再评估回答质量，不要一开始就跑完整的一小时视频。

1. 在 [B 站搜索模拟面试](https://search.bilibili.com/all?keyword=%E6%A8%A1%E6%8B%9F%E9%9D%A2%E8%AF%95)，加上岗位或主题，如“算法工程师”“嵌入式”“Redis”。选择提问清晰、包含讲解或复盘的视频。
2. 在软件填写相同的岗位和主题，选“技术基础”、基础或中等难度、10 分钟，先用键盘完成一题，确认出题、提交、复盘、参考生成和下一题都能工作。
3. 听视频中面试官的一个问题后暂停，自己回答一次。视频是陪练素材，练习页仍由模型出题；请选择与当前题相近的片段，避免把另一道题的回答提交给当前题评分。
4. 点“麦克风作答”，对当前练习题口头回答 20–40 秒，再点“停止麦克风”。核对文字中的英文缩写、专有名词、否定词和数字；修正识别错字后再提交。
5. 对照视频讲解和软件参考答案，检查定义、核心机制、条件与边界。故意只答一个方法名，再补齐机制重新练习，观察反馈是否指出了具体缺失，而不是只看分数高低。
6. 使用同一段口头回答分别试 Paraformer 和 Zipformer，记录错词与等待感受，选择适合自己声音和设备的一款。比较生成模型时保持题目、背景和实际回答尽量相同，避免把不同问题的评分直接当成优劣证据。

戴耳机正常练习时，麦克风转写的是你说的话，通常不会收到耳机里的视频声音；这不是漏录。请暂停视频再作答，避免外放声音与自己的回答混在一起。若完全没有转写，先检查麦克风权限、设备选择及模型下载状态。技术解释和参考评分仍需自行核对。

## 练习设置详解

### 时长、范围和难度

界面提供 10、20、30、45、60 分钟，默认 20 分钟。倒计时从第一题生成成功后开始。时长控制本轮练习的时间，不保证固定题数；题数还取决于模型生成速度和你的回答时间。

| 覆盖范围 | 适合练习的内容 | 简历要求 |
| --- | --- | --- |
| 技术基础 | 概念、工作原理、方案比较、适用边界等通用技术题 | 不需要 |
| 简历项目 | 围绕简历写到的项目、个人贡献和验证方式追问 | 先导入并分析 |
| 技术＋项目 | 技术知识和简历项目相结合 | 先导入并分析 |
| 综合 | 混合覆盖技术与项目话题 | 先导入并分析 |

难度有“基础”“中等”“进阶”三档。目标岗位与关注主题是可选项，主要用于调整选题。例如，岗位填“嵌入式软件工程师”，主题填“Bootloader、通信协议、故障定位”。

练习会把本轮全部已问题目与最近几题的问答摘要作为后续出题的上下文。生成后还会检查文字重复，并由模型判断是否重复考查同一知识点；发现重复时自动重新出题，最多尝试三次。若仍未得到新题，会提示失败并允许重试，不会把重复题当作下一题。模型语义判断仍可能遗漏相似题目。

### 作答方式

每次只回答当前的一道题。文本框应填写你真实说出的内容；如果当时没说到某个机制，不要为了得到高分而在提交前补写成已经说过。需要修正语音识别错字时，可以直接编辑文本。

语音作答的操作顺序是“麦克风作答 → 口头回答 → 停止麦克风 → 检查转写 → 提交回答”。识别中的临时文字会先显示，稳定片段随后加入输入框。使用文本输入时，麦克风和语音模型都不是必需的。

## 导入和分析简历

练习页的“简历背景”支持 PDF、DOCX、TXT、MD，单文件上限 20 MB。应用从文件提取文字；扫描版 PDF 如果没有文字层，需要先自行进行 OCR。读取时最多使用提取文字的前 12,000 个字符，并会在界面提示是否截断。原文件不会被移动或修改。

导入步骤：

1. 在“设置 → 模型与服务”连接当前生成模型；可选择推荐的 API，无需安装 Ollama。
2. 在练习页点击“选择简历”，选中可读取的文件。
3. 点击“分析简历”。API 模式会先提示目的地及本次发送的文字范围；只有明确同意后才发送，拒绝则取消本次请求。本地模式在本机处理。等待模型提取摘要、技能、项目、尚不确定的信息及建议练习主题，请核对原文；错误或遗漏可修改文件后重新分析。
4. 选择“简历项目”“技术＋项目”或“综合”，开始练习。涉及简历内容的 API 请求会逐次弹窗征求同意，包括重新分析、出题、评价和参考生成。

简历分析支持 API 和本地 Ollama。分析的目的只是建立可核对的练习背景，不是替简历补写经历。应用记住所选文件路径和分析结果，重启后会从原路径重新读取文件；如果文件被移动、删除或修改，可能需要重新选择或重新分析。

技术基础练习可以完全跳过本节。若未分析简历就开始项目相关练习，界面会要求先完成分析。

简历分析要求模型返回带摘要和四类字符串数组的 JSON。应用校验字段类型；格式不合法时最多增加一次格式修复，不把模型附带的个人项目参考故事直接展示。若响应因长度上限被截断，应用报错并停止，避免猜测缺失的内容。简历分析使用较大的输出余量，但长材料、小模型或兼容接口仍可能失败；出现错误可缩短材料或换模型后重试。格式校验不能保证事实正确，请核对摘要与原文。

## 选择本地模型或 API

### 使用本地 Ollama

本地模型适合希望让练习请求与简历分析留在本机的用户。可以从 [Ollama 官方 Windows 下载页](https://ollama.com/download/windows)下载安装，按官方说明选择安装位置。安装后在“设置 → 模型与服务”点击“重新检测”；若没有找到程序，可手动选择实际的 `ollama.exe` 路径。

接着在 Ollama 中下载至少一个可用于中文出题和评价的模型，并在模型连接的“高级设置”中选择或填写它的模型 ID。设置页可协助检测服务与模型。简历分析和练习出题共用当前选择的回答模型，但属于不同请求。

如果模型目录在外置磁盘或自定义位置，设置页可以保存对应路径。换电脑或移动目录后需要重新检查路径；仅导入配置备份不会复制模型权重文件。自定义的回答要求只在本地练习模型请求中使用，可用于说明岗位方向和希望被追问的重点，但不能作为项目经历的事实来源。

### 使用 API

模型服务提供 DeepSeek 官方、阿里云百炼北京地域和硅基流动国内接口的预设。选择预设后，通常只需填写对应服务的 API 密钥，再点击“检测并连接”。软件会安全保存密钥、尝试获取模型列表，并实际发送一条简短测试消息；收到有效回答后才显示聊天已连接。测试不会发送简历、个人资料或练习记录，可能产生少量 API 费用。预设并不代表已验证你账户下所有模型的功能，仍需以实际练习结果为准。

“高级设置”中可以修改接口基础地址、填写模型 ID，或从服务返回的列表选择模型。选择“自定义兼容服务”时，高级设置自动展开，需要填写服务商给出的地址；不要填完整的 `/chat/completions` 或 `/models` 请求路径。密钥只会发送到你明确选择的地址，软件不会根据密钥猜测服务商，也不会尝试向其他平台发送它。阿里云的其他地域、工作空间专属地址，以及其他云端或本机兼容服务，都可以在这里配置。

并非所有宣称“兼容”的服务都支持相同参数或模型列表。列表获取失败但已有推荐模型或手动模型 ID 时，软件仍会测试聊天请求；自定义服务返回多个未知模型时，需要你选择聊天模型，软件不会任意选取列表第一项。手动填写及旧版保存的模型 ID 不会因为列表不完整而被自动替换。聊天检测通过只验证连接，练习出题和评价还要求模型能遵循结构化 JSON 输出要求。

API 出题与评价会把本题问题、你提交的回答、岗位与主题等必要文字发给所选服务。技术基础练习不会附带简历内容。分析简历或项目相关练习在发送简历文字、已保存的分析和问答上下文之前，每次请求都会要求你明确同意；拒绝后本次请求取消。模型服务可能收取费用，请自行查看其计费与数据处理政策。

API 密钥单独保存在 Windows 凭据管理器中，不写入可导出的配置 JSON。换电脑或重新设置系统账户时，可能需要重新录入密钥。

## 语音作答和识别模型

语音作答使用“设置 → 模型与服务 → 语音识别”中选择的模型。出题与评价使用“回答生成”模型；这两个环节可以分别配置。本地识别、云端识别和键盘输入是不同选择，不必为了文本练习安装语音模型。

目前接入的识别路线如下：

| 路线 | 已适配的选择 | 使用特点 |
| --- | --- | --- |
| Whisper.cpp 本地识别 | 设置页列出的 GGML Whisper 模型 | 通用安装包使用 CPU，按音频块处理；不要求安装 CUDA。大模型在 CPU 上可能较慢。 |
| Sherpa-ONNX 本地识别 | Zipformer 中英双语流式、Paraformer 中英双语流式 | 支持增量文字；当前打包的是 CPU 运行库。 |
| 语音识别 API | Groq Whisper、Deepgram Nova | 需要对应服务的密钥；录音会发送给所选服务。Groq 按音频段返回，Deepgram 提供流式结果。 |

在模型下拉框看到“未下载”时，选择模型后点击“下载所选模型”。应用只对已经适配的模型和文件布局提供接入；不能把任意 ONNX 或 GGML 文件放进目录就视为兼容。首次下载请等待校验和解压完成，并在必要时确认模型目录的可用空间。

中文与英文术语混合时，自动识别仍可能写错缩写或专有名词。提交回答前应检查转写；项目名、数据和技术术语尤其需要人工核对。语音识别的延迟和准确率依赖音质、设备、模型和硬件。

### 删除不再使用的本地模型

在“设置 → 模型与服务 → 语音识别”选择本地识别引擎和已下载模型，点击“删除所选语音模型”。确认框会显示模型名称与所在位置；确认后删除所选模型文件并刷新下载状态，需要再次使用时重新下载。

同一设置页的“管理已下载的本地生成模型（Ollama）”可在 API 方案下展开。先点击“检测已下载的 Ollama 模型”，选中模型后点击“删除所选 Ollama 模型”并确认。本机 Ollama 服务需要运行；删除通过 Ollama 的接口处理共享权重，而不是删除整个存储目录。其他软件若使用同一模型也会受影响，只支持本机服务。云端 API 模型无需在电脑上卸载。

正在识别、练习、生成或下载时不能删除模型；取消确认不会执行删除。资料、API 密钥与简历分析继续保留。删除当前选中的模型后，请重新下载或改选可用模型再开始练习。

## 如何理解练习反馈

三种模型任务共用回答原则：按领域消除术语歧义；区分通用原理、可能实现与已确认实现；事实不明时明确说明；把解释不足与事实错误分开。没有提供具体模型或方案时，不把某一种架构当成唯一正确答案。评分按本题核心要求的实际覆盖程度给出：仅报方法名称而未解释核心机制属于低覆盖回答，4–5 分要求主要任务已回答且无核心错误。模型仍可能判断失误，应核对具体知识。

技术知识题的复盘包含以下内容：

- **参考评分**：0–5 分的练习指标，只用于比较同一轮中自己的表达，不代表真实招聘评分。
- **本次回答片段**：从你提交的文字中抽取一段可核对原文。如果模型给出的片段无法在原文中找到，应用会退回到回答开头的片段。
- **需要纠正 / 本题漏答的知识点**：指出实际回答中的具体错误及正确理解，或给出题目要求但未回答的知识点及其内容。不会为普通概念题固定追加职责、项目成果、实验验证或取舍要求；没有明确错漏时可以不列建议。
- **参考答案**：提交技术题后，当前回答模型独立生成一份逐点讲解。先解释术语与缩写，再说明定义、原理、因果链和题目要求的方法；不把你的作答直接当成正确答案。生成时持续显示内容，完成后可在本轮问答记录中展开查看。生成失败可单独重试，不丢失已提交回答及评分。

项目与混合题的反馈继续保留事实约束，只检查题目明确要求且回答未说明的方面。需要时可点击“生成参考思路”；出题、评价与参考生成使用同一道题保存的领域、岗位和主题背景，避免中途修改设置导致理解漂移。项目相关练习的参考请求也使用该题的简历摘录及分析；云端每次发送前单独确认，不附带你的作答。技术基础练习不附带简历。软件不生成未经核实的第一人称项目经历。复盘时建议先对照原问题，标记自己实际讲清楚的内容；再查看简历和项目资料，补上能够证明的步骤、理由与结果。对于不确定的事实，先核查，不要把模型推测写进简历或练习答案。

参考生成完成后点击“下一题”。本轮全部已问题目会进入防重复检查，最近的作答摘要另行提供；新的候选题会经过精确重复与模型语义检查，重复时最多重新出题两次，仍重复则提示重试而不展示重复题。同一领域的不同考点允许继续练习，重复校验增加一次短模型请求，并不能保证模型始终正确区分所有相近问题。页面会保留本轮已回答的题目、提交文本、参考答案、各题参考评分和平均分，便于在当前运行期间回看。不要把当前轮的屏幕记录当作长期保存的正式成绩单。

### 数学公式显示

参考答案、技术纠错说明与练习题支持 LaTeX 公式显示，包括分数、根号、上下标、求和及矩阵。模型在涉及计算时会被要求给出公式并解释符号和必要维度；例如注意力计算中的 Q、K、V 与缩放因子。使用 `\( ... \)` 表示行内公式，`\[ ... \]` 或 `$$ ... $$` 表示独立公式。公式无需代码块，也无需额外开启开关。显示资源随软件打包，显示公式本身无需联网。

流式生成中尚未闭合的公式暂时保留文本，完整后排版；格式错误或不支持的命令也保留原文。长公式可在公式区域横向滚动。排版不会验证数学推导是否正确，仍需核对模型提供的内容。

## 界面、数据保存与备份

按住顶部标题栏横线上方的文字或空白区域可拖动窗口，按钮保持各自的点击功能；设置页和悬浮窗也可从标题栏拖动。内容区的滚动条采用透明轨道，避免覆盖标题栏与圆角。 窗口四边与四角均有贴近可见边框的拖动区域。练习设置、对话、复盘之间的分隔线可拖动调整比例；窄窗口改为上下分隔。比例在本机保存，隐藏某个区域后仍保留其设置；也可选中分隔线后按方向键微调。

最小化、最大化/还原和关闭按钮位于右上方的独立行，窗口缩小时也保持在其他操作按钮上方。

窗口支持缩放和调整大小；较窄时，题目与复盘内容排在设置区前面。顶部可控制练习设置区和回答复盘区的显示，窗口可设置置顶。设置中可选深色或浅色皮肤，并调整透明度。使用悬浮窗时，它显示当前练习问题和复盘摘要，适合在另一块屏幕或较小窗口中查看；完整操作仍在主窗口完成。

模型选择、接口地址、语音模型、目标岗位、关注主题、简历路径及练习配置会自动保存到应用的本机配置。简历分析在保存时会与文件哈希关联；重新读取后如文件内容不同，旧分析不会被当成新文件的分析结果。安装新版本时保持同一应用身份和用户数据目录，通常不需要重新配置。

“设置 → 个人资料 → 配置保存与备份”提供“导出配置文件”和“从文件导入”。导出的 JSON 包含模型设置、部分本地程序和模型路径、练习配置、简历路径与已保存的分析，因此可能含有敏感信息，应存放在可信位置。它不包含 API 密钥，也不复制简历原文件或模型权重。导入后请检查本地路径；模型目录与 Ollama 程序路径可能需要重启应用才会生效。

诊断日志显示最近的状态和耗时，用于排查模型连接、识别与出题失败。日志不会刻意记录完整音频、简历正文或 API 密钥。遇到问题时可先查看“设置 → 诊断日志”，再核对服务状态和模型 ID。

## 历史练习与用量查询

从 1.0.14 起，每场模拟练习自动保存在本机。点击顶部“历史”，或打开“设置 → 历史会话”，可查看过去的题目、提交的作答、评分复盘和生成的参考答案。重新启动、覆盖安装新版本后，已保存的场次仍可查询；旧版本没有保存的记录不能补回。

1. 点击“历史”后，选择一场练习查看详情。
2. 输入关键词搜索题目、回答或复盘；也可选择本机日期，点击“查询 / 刷新”。默认显示最新 100 场，用日期或关键词查找更早记录。
3. 点击“导出 Markdown / JSON”，选择文件位置。Markdown 便于阅读，JSON 保留结构化内容和接口返回的用量。
4. 已结束的场次可以点击“删除本场”。删除不可恢复；正在进行的场次需要先结束练习。

详情中的用量表按出题、评价、参考生成等阶段及模型分开统计返回请求、输入 token、缓存命中和输出 token。缓存命中是输入 token 的一部分，不能再加一次。部分接口不返回用量，失败或取消的请求也可能被服务商计费，因此表格不是最终账单；本地 Ollama 的 token 不代表 API 费用。

记录保存在 `%APPDATA%\app.interviewcue.local\history.sqlite3`，包含文字内容，不保存原始音频，也不写入 API 密钥。它与配置备份是两个文件：导出配置不会包含问答历史。需要备份全部历史时，先正常退出软件，再复制这个数据库文件。导出的问答文件可能包含个人经历，请自行选择可信的保存位置。保存失败时软件会显示错误，请检查磁盘空间和目录权限。

## 软件内更新

从 1.0.11 起，在“设置 → 软件更新”点击“检查更新”。软件显示当前版本；发现更新时显示新版本和更新说明，再点击“下载并安装”。安装包下载完成并通过发布签名校验后，软件会保存最新配置、关闭程序并启动覆盖安装，安装完成后重新启动。模型设置、密钥、岗位资料、简历分析和已有模型路径继续保留，不会因此重新下载本地模型。

正在练习、语音转写、生成回答或下载模型时，请先结束相应操作再安装。检查更新只访问发布信息，不发送简历、个人资料或 API 密钥。检查失败会显示连接错误；下载失败或签名校验失败不会安装更新，可重试。下载进度随网络返回的文件大小显示。

更新包来自 GitHub，下载速度受访问 GitHub 的网络情况影响。当前没有独立镜像或 CDN；按钮旁也会显示这一说明。旧版本首次需要覆盖安装一次 1.0.11 或更高版本，之后可直接在软件内更新。

## 隐私与数据流向

| 操作 | 数据去向 |
| --- | --- |
| 键盘填写技术题回答，回答模型为本地 Ollama | 问题与回答发给本机 Ollama 服务。 |
| 使用云端回答模型做技术题练习 | 问题、回答及相关练习设置发给所选 API；不附带简历内容。 |
| 本地分析简历 | 从本机文件提取的文字发给本机 Ollama 服务。 |
| 使用 API 分析简历 | 每次分析前弹窗确认；明确同意后把最多 12,000 字的简历文字发送到当前所选 API。 |
| 使用云端回答模型做项目相关练习 | 每次发送前弹窗确认；同意后才把必要的简历摘录和分析、题目或回答发给所选 API。 |
| 使用本地语音识别 | 麦克风音频在本机识别模型中处理。 |
| 使用语音识别 API | 麦克风音频发给所选语音服务。 |
| 导出配置 | JSON 文件保存在你选择的位置；不包含 API 密钥或简历原文件，但可能包含简历分析与路径。 |
| 保存练习历史 | 题目、作答、复盘、参考答案及用量保存在本机数据库；导出时写到你选择的文件，不额外发送给云端。 |

如果使用第三方 API，服务端如何留存和处理数据由相应服务的条款决定。含个人信息的简历建议在决定发送前阅读弹窗内容和服务政策。应用不会替你判断某段个人资料是否适合上传。

## 常见问题

**点击“开始练习”后没有题目。** 先检查“回答生成”的模型 ID、接口地址和密钥。使用 Ollama 时确认程序已安装、服务可连接、模型已经下载；使用 API 时测试聊天请求是否成功。仅能获取模型列表不等于出题请求一定可用。

**项目练习要求先分析简历。** 这是当前流程的前置条件。导入有可提取文字的简历并分析，可直接使用当前 API，不需要切换到 Ollama。

**PDF 导入失败或分析内容很少。** 检查文件是否为扫描图片、是否超过 20 MB。扫描版先进行 OCR，再重新导入。提取文字最多使用前 12,000 个字符，较长简历可把重要项目放在前面。

**语音作答没有文字或延迟明显。** 在“音频设备”中确认麦克风、系统权限和音量；在“语音识别”中确认所选模型已经下载或 API 密钥有效。不同识别路线的增量速度不同；也可以暂时改用键盘输入完成练习。

**转写把技术术语写错。** 提交前直接修改文本。关注主题和简历中的真实术语可以帮助部分识别路线，但不能保证所有缩写正确；请以原始发音、项目文档和自己的核对为准。

**换版本后找不到模型或简历。** 先检查模型目录、`ollama.exe` 与简历原文件是否移动。应用保存的是路径和分析，并不会把大型模型或简历复制进配置文件。可从备份 JSON 恢复设置，然后重新检查路径和 API 密钥。

**评分看起来不合理。** 分数由模型依据当前提交文本给出，可能误判。优先看它引用的回答片段是否真实，以及“可补充的方面”是否符合题目；必要时重新表述同一知识点进行下一轮练习。

**启动提示找不到 `cublas64_13.dll`。** 这是旧安装包依赖开发机 CUDA 运行库造成的打包问题。从 1.0.12 起，通用安装包移除该启动依赖，不需要安装 CUDA。旧版无法启动时，直接下载新版安装包并覆盖原安装目录；设置、简历分析和模型路径继续保留。

## 从源码构建

仓库包含 Tauri、React 和 Rust 实现。普通使用者可以安装已提供的 Windows 安装包；自行构建需要 Node.js/npm、Python 3、Rust 的 Windows MSVC 工具链、Visual C++ 构建工具、CMake，以及本地语音依赖所需的 LLVM/libclang。具体可用版本以项目锁文件和构建脚本为准。

```powershell
npm ci
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/build-windows.ps1
```

发布构建需要配置 `TAURI_SIGNING_PRIVATE_KEY` 指向维护者的发布私钥，或使用本机 `%LOCALAPPDATA%\MockInterviewRelease\signing.key`。私钥不进入仓库或安装包。自行分发的派生版本应生成自己的签名密钥，并修改 `tauri.conf.json` 中的公钥和更新源。若只运行开发版，可使用 `npm run tauri dev`，不需要发布私钥。

发布脚本固定构建不依赖 CUDA 的 CPU Whisper 版本，不再根据开发机是否安装 CUDA 自动改变用户所需的运行环境；CPU 指令基线为 AVX2，不使用开发机专属的 AVX-512 优化。Sherpa-ONNX 双语模型仍使用打包的 CPU 运行库；Ollama 的加速由其自身管理，不受此改动影响。构建和发布前均检查主程序与打包语音运行库的普通导入、延迟导入，发现 CUDA DLL 依赖时拒绝发布。构建完成后，Windows 安装包位于 `src-tauri/target/release/bundle/nsis/`。

如果只检查前端，可运行 `npm run build`；Rust 代码可运行 `cargo check --manifest-path src-tauri/Cargo.toml`。

维护者发布流程：使用 `npm run sync-version -- 版本号` 同步应用版本，完成签名构建，将提交与 `v版本号` 标签推送到仓库，再运行 `npm run release -- --notes-file 发布说明文件路径`。脚本先创建草稿发布，上传安装包、签名、校验和及 `latest.json`，确认更新文件齐全后再公开该版本。可先用 `npm run release:dry-run -- --notes-file 发布说明文件路径` 检查产物，不上传文件。指定了 `CARGO_TARGET_DIR` 时，可用 `--installer` 指定该目录中对应版本的安装包。发布私钥需单独妥善备份，以便后续版本继续被已安装应用验证。
