# 中文夹英文术语的识别背景

本版以通用中英双语识别模型作为覆盖面的来源。界面中的「通用技术／人工智能／通信与网络」目前只提供简短主题背景，供支持提示的识别服务参考；它不训练模型，也不声称覆盖所有术语。原始转录保留在界面中，判别模型不得把背景标签当成听到的事实。

## 优先考察语音训练数据，而不是行业术语表

- [WenetSpeech](https://github.com/wenet-e2e/WenetSpeech)：真正用于训练中文 ASR 的多领域音频与转录语料，包含访谈和会议场景。仓库代码许可与语料下载条款需分别核对；下载语料需要按官方流程申请。它可辅助模型选择和后续训练，不是可直接导入 Whisper 的「术语词表」。
- [ASCEND](https://github.com/HLTCHKUST/ASCEND)：中文英语混说的连续对话音频与转录，适合评估代码切换。约 10.62 小时，规模较小，且香港说话场景与普通话技术面试存在域差异。
- [TALCS 论文](https://arxiv.org/abs/2206.13135)：普通话英语混说语音训练／评估语料。使用前还需核对具体下载页、语料许可与面试场景的差异。

上述语料的转录文本可以统计常见中英混用写法，但训练或适配识别模型需要对应音频、标注和模型训练接口。单独抽出文本词频，并不能让现有识别模型正确听到发音。文本任务词表（例如 THUOCL）与传统 ASR 发音词典（例如 BigCiDian）都不能冒充已用于本版 ASR 的训练数据；本版没有自动导入它们。

## 为什么不把整张词表送给 Whisper

Whisper 的 `initial_prompt` 只提供有限长度的文字上下文，不会重新训练声学模型，也不能容纳一万多个候选词。无关词过多可能把识别结果拉向背景预期，尤其会误改相近术语。当前程序只送短领域描述；在获得可复现的语音错误样本后，再决定是否改用原生支持上下文偏置的识别模型，或基于合适语料训练／适配模型。

## 后续接入词包时的边界

先确定使用的 ASR 模型或接口是否真正支持热词、发音词典或语音微调，再按它的机制设计数据。训练／评估样本应保留音频、逐字转录、中英文术语写法、来源和许可；按说话人或整场面试划分，避免相同录音泄漏。选择领域不能在音频证据不足时强制替换转录，也不能把词表当作回答事实。只有同一批中文技术录音显示术语识别改善、误植词没有明显上升，才应默认启用新的识别策略。
