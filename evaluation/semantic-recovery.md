# 转录后的问题理解

这条流程处理已经得到的转录文字，不修改原始转录，也不声称能恢复音频里所有丢失的信息。

## 固定流程

1. `submit_task` 判断当前请求及说话角色，返回来源 ID、完整性状态、简短候选和原句上的小范围纠错。历史背景只能帮助理解当前请求。
2. 程序检查来源、原文位置、编辑是否重叠，以及编辑中的显式数字和否定。有效编辑只应用到对应原句，构成保留原句范围的候选。来自本地元数据的近似拼写也只作为候选。
3. 对需要消歧的请求，`verify_task` 独立评估每个候选的口述支持度、领域适配度，以及事实关系是否保持。程序排除改变关系的候选，再按 `2 × context_fit + spoken_fit` 排序。该分值是候选之间的序数评分，不是经过校准的置信概率。
4. 选定解释后清除前一假设的回答要点，避免错误听写通过旧元数据再次进入回答。已接受的问题继续生成回答，检索只提供可选依据。

复核只看原句、背景和候选，不把提取器自己生成的回答要点、条件说明当成原文事实。候选的自由改写可能省略或扩展关注点，因此同时保留程序从原句生成的小范围纠错版本。

结构化调用统一使用低随机性设置。DeepSeek 非思考模式显式设置 `temperature=0`；这降低采样波动，不能保证服务端完全确定。参数支持以[官方 API 文档](https://api-docs.deepseek.com/api/create-chat-completion/)为准。

## 未完成片段与重复

- 主题名词不能自行补成询问型号、配置或方法的任务。程序检查原文中的通用提问动作或疑问关系；缺少时保留片段。
- 未完成请求最多保留 4 个来源，20 秒后失效。线上模式不能跨越候选人的麦克风回答继承旧请求。
- 下一次真正的转录更新可以补全片段；计时、音量变化本身不产生额外模型调用。原判别间隔继续生效。
- 同一来源和同一原文版本的改写保留当前任务。原文确实变化时仍可修正。
- 一次判别最多两次模型调用，没有自动付费重试。明确且无需消歧的原句可以省去第二次调用。

## 资料校验

确认问答和原文摘录逐条校验。一个过期索引段落不能清空其他有效问答；授权范围或整体大小检查失败时仍不发送该组资料。失效摘录不会被当作事实使用。原始资料不由此流程改写。

## 验证方法与边界

- 原生测试覆盖编辑位置、重叠、数字和否定保护、候选评分、来源不变、残句继承及过期。
- 界面测试检查未完成片段传递、完成后的清除、有效短追问、音源隔离及现有调度间隔。
- `historical_pipeline_replay` 是显式启动的付费测试：要求固定输入哈希、全新结果文件和请求预算，调用生产提取、检索、资料选择及流解析。私有转录、题库副本和输出放在忽略的 `outputs/` 中。
- 较早的文字记录可能缺少原始分段时间；按最终文字重建的窗口不能证明完整现场音频表现。候选生成与评分仍依赖所选模型，未知术语、严重丢字和混合音轨中的角色混淆仍需实际检验。

不要以“输出非空”作为理解正确的唯一指标；应分别检查请求动作、主题与关注方面、事实关系、重复触发以及回答是否用到了有效依据。
