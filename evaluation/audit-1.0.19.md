# 1.0.19 follow-up extraction and display audit

The reported transcript asks how to improve a model's generalization ability, after a question asking for its definition. ASR rendered 泛化能力 as 方法能力. A screenshot alone cannot reveal the classifier's raw response or prove which gate blocked this particular event; the local history contained no matching session. The following failure paths were reproduced independently.

The display gate accepted a new task only when its action was `show` and its relation was `new`. Consequently `show/follow_up` was discarded even for a stable, different source. A `revise/follow_up` from a new partial source was also discarded until final. Different transcript sources can now start a new answer task for either `new` or `follow_up`, with either display action. Same-source provisional rewording stays hidden; a stable source can revise once. `repeat`, `none`, `wait` and `keep` do not start another task.

The five-second scheduler merges adjacent transcript fragments. Its batch can contain an interviewer question followed by a candidate's unfinished answer, especially in a single-track video. The semantic prompt now explicitly identifies the last request within the whole new batch. Subsequent answer fragments must not cancel that request; a batch with only an answer must not re-extract a question from history. Contextual ASR correction remains a model operation, with an example of the reported generalization follow-up. There is no application-level 方法能力-to-泛化能力 dictionary and no extra classification call. The input labels distinguish the new batch from historical dialogue.

An identical extracted question no longer regenerates an answer merely because the classifier changes focus or terminology metadata. Diagnostic records distinguish accepted tasks from suppressed same-source or unchanged-question results, without storing extra transcript content in diagnostics.

The scheduler itself is unchanged: its default minimum interval is five seconds, with no periodic request when text is unchanged. Online and video modes use system audio for pause detection; offline mode uses microphone audio. Candidate microphone speech in online mode only supplies dialogue context.

Validation: the scheduler, dialogue-context, question-transition and browser integration suite passed all 11 tests, including 14 transition assertions. The browser replayed the reported multi-fragment video scenario with `show/follow_up` and a final unfinished candidate fragment; the previous definition was replaced by the improvement question. Candidate-only output and erroneous redisplay with changed metadata did not cause a third answer. Existing interval, cancellation, audio-source, introduction and context checks passed.

Using the production system prompt, user template and JSON schema, a local qwen3:4b-instruct run correctly extracted 如何提升模型的泛化能力 in all three targeted scenarios: the follow-up alone, followed by stable answer fragments, and followed by an unfinished partial. These were synthetic text tests, not microphone or network measurements. A broader 13-case diagnostic run passed 11 cases but still failed PPO/BPO correction and inclusion of the subject in a multi-fragment engineering question. Small-model semantic accuracy remains a limitation; this release does not claim that arbitrary transcription errors or all context-dependent questions are resolved.

The signed executable and NSIS installer built successfully. Portable-runtime verification passed for four Windows binaries without CUDA DLL imports. Version 1.0.19 covered the existing installation; the installed binary matched the build, configuration files were byte-identical immediately after installation and the existing desktop and Start menu shortcuts retained their targets. Installed startup passed with a Windows-only PATH and no CUDA environment variables. The packaged semantic backend also extracted the reported multi-fragment follow-up using the local model, including with `isFinal=false`. Native cancellation interrupted a stalled local HTTP response in four milliseconds, and closing the native window flushed the profile and exited normally.
