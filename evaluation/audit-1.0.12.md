# 1.0.12 缺陷排查记录（2026-10-09）

## 排查范围与确认的问题

本次检查启动依赖、配置读写、关闭与更新、练习状态、音频启动及回答请求取消。以下是已确认的缺陷，不是模型回答准确率评估。

| 问题 | 触发条件与修复 |
| --- | --- |
| 通用安装包依赖开发机 CUDA | 旧程序直接导入 `cublas64_13.dll`，没有对应环境时连 API 模式也无法启动。公开包固定使用 CPU Whisper、关闭主机特性自动选择，并在构建与发布前检查 PE 普通及延迟导入。 |
| 读取失败覆盖配置 | 配置加载失败后，默认设置仍会触发自动保存。读取失败时禁止写回，保留原文件；显式导入成功后才恢复保存。 |
| 快速退出丢失编辑 | 自动保存有 350 ms 防抖，关闭程序可能早于保存。窗口关闭、快捷键退出和安装更新前串行写入最新快照；写入失败保留窗口并显示原因。 |
| 首题生成时切换模式 | 会话尚未标记开始，模式切换未检查待处理请求。现在操作进行中也阻止切换和修改模型配置。 |
| 麦克风迟到启动 | 启动麦克风期间结束练习或时间耗尽，迟到结果仍可能重新开启采集。启动过程记录会话代次，结束使其失效，完成后清理采集与监听器；到时结束复用同一清理路径。 |
| 音频启动假成功 | 系统采集线程创建成功不代表设备初始化成功，识别流失败也可能继续返回成功。系统音频增加启动确认，缺失的指定设备明确报错；识别引擎预先验证，启动失败释放已打开资源并恢复默认设备。 |
| 取消后等待网络 | 旧实现只在下一块数据到达后检查取消，服务端不发送响应头时不能及时退出。取消现在同时唤醒等待响应头和流数据的异步操作。服务端是否停止计算仍由其自身决定。 |
| 更新删除中文快捷方式 | NSIS 更新模式跳过新建英文快捷方式，但安装钩子先删除已有中文入口，后续重命名没有源文件。现在保留属于当前安装的中文入口，仅迁移旧名称和已有英文入口。 |

## 自动验证

- `node --test --experimental-strip-types evaluation/*.test.mjs`：36 项全部通过，包括新增的配置读取失败、即时退出保存、待处理首题和麦克风启动结束/超时复现。
- `cargo test --release --lib`：86 项全部通过，包括缺失输出设备不能报告启动成功、取消唤醒以及已有流解析、模型协议与上下文测试。
- 修复公式渲染测试与另一测试共用端口的问题；这是并行测试隔离问题，不是产品渲染缺陷。
- 构建流程使用 `--ci`，避免 Windows PowerShell 丢弃空密码环境变量后签名工具停在不可见交互提示上。

## 安装程序与原生运行验证

- 签名 Windows NSIS 安装包构建成功，主程序及三个语音 DLL 的导入检查通过，无 CUDA DLL 导入。
- 以 `/S /UPDATE` 覆盖安装到现有目录；`config.json` 与 `local-runtime.json` 在安装前后的 SHA-256 相同，安装后程序与构建产物匹配。
- 覆盖安装后直接检查中文桌面及开始菜单快捷方式存在且目标正确，没有通过验证脚本重建入口来掩盖安装器行为。
- 将启动环境 PATH 限制为 Windows 系统目录并移除 CUDA 环境变量，安装后的程序正常进入练习页，隐私设置应用无错误。
- 原生 IPC 向无响应头的合成回环 HTTP 服务发送不含密钥或个人背景的测试请求。旧实现不能在 1.5 秒内完成取消；修复后本次测得 5 ms。该数字是本机取消耗时，不是模型生成延迟基准。
- 从原生窗口关闭路径退出，保存完成后进程正常结束，未遗留应用进程。
- 安装包 SHA-256：`C461AB62A67932979ADCB34316A86DB2BF9C8D1F6569704C74323B2627D5ED02`。

## 验证边界

测试通过不能证明没有其他缺陷。未穷举耳机、蓝牙驱动、运行中设备拔插、所有 API 服务和真实长时会话；模型幻觉、术语歧义和评分校准仍需要独立样例集评估。本次不把合成流程测试当成语音识别或回答质量的统计证据。

旧版记录保留在 `validation.md`，其中 CUDA 构建和旧 UI 描述属于当时版本，不代表 1.0.12 的发布配置。
